Privacy Policy

Last updated: 1 October 2026 (added Send files)

Lanyard has two parts. Remote control (media keys, touchpad, keyboard) works only between your phone and your PC and involves no server. Send files works on your own Wi-Fi: the Lanyard program on your computer serves the page and introduces the two devices, and files go straight between them, so no server of ours is involved. Only if you choose to use a Send files server (your own, for sending over the internet) does a small server introduce devices and, when a direct connection is impossible, relay encrypted data. Unless you choose to create the optional account described below, the developer collects no personal data, and the app contains no analytics, advertising or tracking. Your files are never stored on any server.

What stays on your devices

  • Pairing data. The PC keeps a list of phones you have approved (a name and a public key that you can revoke). The phone keeps the key for each PC it is paired with, plus your settings (theme, step sizes and similar). This is stored only on those devices. phone-remote rotate on the PC revokes every phone.
  • Media commands. Play, pause, seek, volume and similar commands travel directly between your phone and your PC over your local network, or over Bluetooth. The PC agent also reads the title and playback position of the current media session so the phone can show what's playing. That information is shown on your phone and is not sent anywhere else.
  • Logs. The desktop agent (Windows, macOS or Linux) writes a local activity log on the computer (viewable in its dashboard). It is never uploaded.
  • Crash screen. If the Android app crashes, it shows the error details on screen so you can choose to copy them into a bug report. Nothing is sent automatically.

Send files: what the server sees (only if you use one)

By default Send files runs on your computer and only on your home network; the points below apply to a Send files server you set up yourself for sending over the internet.

  • File contents. Files travel directly between devices, encrypted (WebRTC/DTLS). They never pass through the server unencrypted and are never stored. When a direct route is impossible the relay forwards the same encrypted traffic without being able to read it.
  • Connection setup. To connect two devices, the server forwards short setup messages between them (random device ids and network-address details needed to connect). These are held in memory only while connected and are not written to disk.
  • IP addresses. As with any internet service, your IP address is visible to the server and the relay while you are connected. The relay may write connection details (IP addresses and times) to operational logs. Those logs rotate automatically by size and are kept only for a short time (typically days), used only to keep the service running and to deal with abuse.
  • Sharing. People you give a room link or code to can see the file names you send them and your device's network address, as with any peer-to-peer transfer. Only share a room with people you trust, and use a room password for sensitive files.
  • Who runs the server. The address of the Send files server is set by whoever built or configured your copy of the app (you can change it under Settings → Send files). If you run your own server, only you see this data.

The optional account

You never need an account. If you create one, it is run on a server set up by whoever built your copy of Lanyard (for the public release, the address in Settings → Account). Control of your computer still goes directly between your phone and computer on your own network and never passes through the account server.

  • What the account stores. Your email address; for each device you add, a name, its type (phone or computer), platform (such as Android or Windows), a public key, the date it was added or removed, and, for a computer, the identifier and key fingerprint phones use to recognise it on your network; sign-in sessions (stored as one-way hashes); and the time of the last certificate issued to each device. The account service does not store your files, your media, what you control, or where your devices are.
  • What it is used for. Signing you in with an emailed code (or Google or Apple sign-in where offered), showing you your devices, and giving each of your devices a short-lived certificate (about 30 days) that your computers accept, even offline, instead of scanning a code. Computers ask the server every few minutes to hours for the list of removed devices so a lost phone stops working.
  • Who sees it. The person running the account server can see the data above. Emails are sent only to deliver your sign-in code. Nothing is sold or shared for advertising.
  • Logs. Like any internet service, the server and the reverse proxy in front of it see your IP address when you connect and may keep short-lived operational logs.
  • Removing it. You can remove any device, sign out, or delete the whole account (email and every device) at any time from My devices or from the phone app's Settings. Deleting is immediate. Removing a device takes effect on a computer the next time it checks the removal list, normally within 15 minutes, and a computer that is offline keeps accepting a removed phone's existing certificate only until that certificate expires (up to about 30 days, plus a 14-day grace period) unless it has checked the list meanwhile.

Permissions the Android app asks for

  • Network and Wi-Fi state, multicast. To find your PC on the local network and talk to it. The Files tab opens Send files in your browser, so file transfer itself needs no extra permission.
  • Bluetooth (connect, advertise). For Bluetooth mode, where the phone acts as a keyboard / media-key device. Android groups these under "Nearby devices".

The app does not use your camera permission (QR scanning uses the system scanner), location, contacts, microphone or storage.

Network traffic

Send files transfers are always encrypted end to end (WebRTC), and a Send files server you set up yourself should use HTTPS. Remote control between your phone and your computer uses an encrypted HTTPS connection that the phone pins to your computer's own key, so other people on the same Wi-Fi cannot read or change it. Phones with an older version of the app use plain HTTP until you switch that off in the computer's dashboard. The computer only accepts connections from private (LAN) addresses and requires a paired device.

Children

The app is not directed at children and collects no data from anyone.
